# 犬の登録画面 E2Eテスト項目

犬の新規登録画面 `/dogs/new` の現行実装を基準に、E2Eテスト項目を洗い出しました。登録後の犬詳細画面の内部仕様は別画面のテスト仕様として扱います。

## 1. 画面遷移・初期表示

正常系：

- 犬一覧のヘッダー追加ボタンから登録画面へ遷移する
- 犬一覧の空状態にある追加ボタンから登録画面へ遷移する
- Cancel、Save、犬画像、Change photo、Name、Breed、Gender、Birthday、Goalが表示される
- 初期状態では犬画像のプレースホルダーが表示される
- Name、Breed、Gender、Birthdayは未入力で表示される
- Goalは既定の日次目標時間で表示される
- NameとGenderが未入力のためSaveは無効である
- フォーム全体をスクロールし、すべての項目へ到達できる

異常・境界系：

- 画面を開き直したとき、キャンセル済みの入力が意図せず残らない
- 小さい画面とキーボード表示中でもCancel、Save、全入力項目へ到達できる
- Dynamic Typeを最大にしても入力項目や操作ボタンが欠けない
- VoiceOverでCancel、Save、画像変更、各入力項目、目標操作を識別できる
- ライトモード・ダークモードの双方で内容を判読できる

## 2. Cancel操作

正常系：

- 未入力状態でCancelを押すと犬一覧へ戻る
- 入力途中でCancelを押すと登録せず犬一覧へ戻る
- Cancel後、犬一覧に未保存の犬が追加されない

異常・境界系：

- Cancelを連続タップしても余分な画面まで戻らない
- 画像選択中または誕生日Modal表示中に戻る操作を行っても状態が破損しない
- 保存リクエスト送信中にCancelできない、または二重遷移しない
- 入力済み状態で確認なしに破棄する仕様が意図どおりである

重要な現状差分：現行実装は未保存変更の確認ダイアログを表示せず、Cancelで即座に戻ります。また、Cancelボタン自体は`submitting`中も明示的に無効化されません。

## 3. 必須入力とSave活性

正常系：

- NameとGenderを入力するとSaveが有効になる
- Breed、Birthday、Photoは未入力でもSaveできる
- Nameの前後空白は保存時に除去される
- Genderの前後空白は保存時に除去される
- Breedの前後空白は保存時に除去される
- Breedが空白だけの場合、未設定として保存される

異常・境界系：

- Nameが空文字の場合Saveは無効
- Nameが空白だけの場合Saveは無効
- Genderが未選択の場合Saveは無効
- Nameだけ入力してもSaveは無効
- Genderだけ選択してもSaveは無効
- 有効状態からNameを消すとSaveが再び無効になる
- Saveを連続タップしても登録リクエストは1回だけ送信される
- 送信中はSaveが無効になり、二重登録を防止する

重要な現状差分：クライアント側の必須判定はNameとGenderが空白でないことだけです。文字数、禁止文字、重複名は検証していません。

## 4. Name入力

正常系：

- ひらがな、カタカナ、漢字、ラテン文字の犬名を入力して保存できる
- スペースを含む犬名を保存できる
- 絵文字を含む犬名について、仕様どおり保存または拒否される
- 入力後にキーボードを閉じても値が保持される
- 保存後の詳細画面と一覧に同じ犬名が表示される

異常・境界系：

- 極端に短い名前と長い名前を仕様どおり扱う
- 改行、制御文字、前後空白を含む入力を安全に扱う
- 空白のみの入力を保存しない
- 同じ名前の犬がすでに存在する場合の仕様を確認する
- HTMLやスクリプト風文字列を入力しても表示やログが破損しない
- 非常に長い名前でもフォームと詳細画面のレイアウトが破損しない

重要な現状差分：Nameの最大長や文字種制限はモバイル画面にありません。同名登録もクライアント側では拒否しません。

## 5. Breed入力

正常系：

- 犬種を入力して保存できる
- 犬種を空欄のまま保存できる
- 日本語、英語、複合犬種名を保存できる
- 保存後の詳細画面と一覧に犬種が表示される

異常・境界系：

- 空白だけの犬種は未設定として保存される
- 非常に長い犬種名でもフォームが破損しない
- 改行、制御文字、絵文字を安全に扱う
- Breed入力中にNameやGenderの値が失われない

重要な現状差分：Breedにも最大長や文字種制限はありません。

## 6. Gender選択

正常系：

- Genderを押すとiOS Action Sheetが表示される
- Male、Female、Otherをそれぞれ選択できる
- 選択した値がフォームに表示される
- 選択後にSaveが適切に活性化する
- GenderのAction SheetでCancelを押すと選択値を変更しない
- 保存後の犬データに選択したGenderが反映される

異常・境界系：

- Action Sheetを連続して開いてもクラッシュしない
- Action Sheet表示中にアプリをバックグラウンドへ移動しても状態が破損しない
- 選択値が不明な値の場合、未選択表示へ安全に戻る
- VoiceOverで各選択肢とCancelを識別できる

## 7. Birthday選択

正常系：

- Birthdayを押すと年・月・日のModalが表示される
- 初期状態では年・月・日が未設定である
- 年を選択するまで月を選択できない
- 月を選択するまで日を選択できない
- 年だけを選んで保存できる
- 年と月だけを選んで保存できる
- 年月日すべてを選んで保存できる
- ModalのSaveで選択内容をフォームへ反映する
- ModalのCancelで一時選択を破棄する
- 現在の年から1990年まで選択できる
- 月に応じて選択可能な日数が変わる
- うるう年の2月29日を選択できる
- 平年の2月29日を選択できない
- 31日から30日しかない月へ変更した場合、無効になった日をクリアする
- 年をUnknownへ戻すと月と日もクリアする
- 月をUnknownへ戻すと日もクリアする
- 保存後、ロケールに応じた形式で誕生日が表示される

異常・境界系：

- 1990年より前の誕生日が必要な場合の制約を確認する
- 未来の日付を選択できないことを確認する
- 現在年で未来の月日を選べる場合、その扱いを確認する
- Modal外タップ、システム戻る、アプリ中断時に一時選択が不正に確定しない
- 年月日の高速な連続変更で不正日付を保存しない
- Dynamic Type最大時でも3列の選択肢と操作ボタンへ到達できる

重要な現状差分：年の範囲は1990年から現在年です。現在年の未来月日を明示的に除外する処理は確認できないため、未来日を登録できる可能性があります。

## 8. Goal設定

正常系：

- 初期状態でDailyが選択され、既定の目標時間が表示される
- スライダーで日次目標を変更できる
- 目標時間は定義されたstep単位で変化する
- 日次目標の最小値と最大値が表示される
- DailyからWeeklyへ切り替えられる
- Weeklyへ切り替えると目標時間が周期に合わせて変換される
- Weeklyの最小値・最大値に切り替わる
- WeeklyからDailyへ戻した場合も周期に合わせて変換される
- 保存後、犬詳細画面に選択した周期と目標時間が反映される

異常・境界系：

- スライダーを最小値未満へ動かしても最小値に収まる
- スライダーを最大値より上へ動かしても最大値に収まる
- 周期切り替え後の換算値が範囲外になる場合、正しくclampされる
- スライダーの高速操作中にSaveしても表示値と送信値が一致する
- @expo/uiのSwiftUI Sliderが利用できない場合に画面全体がクラッシュしない
- VoiceOverから周期選択と目標時間を変更できる

## 9. Photo選択

正常系：

- Change photoを押すと写真ライブラリ権限を要求する
- 権限許可後、画像ライブラリが開く
- 画像以外は選択対象にならない
- 選択画面で編集・クロップできる
- 選択した画像のプレビューが表示される
- 選択をキャンセルした場合、画像を変更しない
- ファイル名がない画像には既定名`avatar.jpg`を使用する
- MIME typeをアップロード可能な形式へ正規化する
- 写真未選択でも犬を登録できる
- 写真選択後に登録すると画像がアップロードされ、詳細画面に表示される

異常系：

- 写真ライブラリ権限を拒否した場合、ローカライズされた説明Alertを表示する
- 権限拒否時に画像ライブラリを開かない
- 権限を恒久拒否した場合の再許可方法が分かる
- 画像選択結果にassetがない場合、クラッシュしない
- 非対応MIME typeを安全に扱う
- 非常に大きい画像を選択した場合、メモリ不足や長時間停止を起こさない
- 壊れた画像ファイルを選択した場合、登録失敗を明示する
- 画像プレビューの読み込み失敗時にプレースホルダーへ戻る
- 画像アップロード失敗時に犬登録の成否と再試行方法を明示する

重要な現状差分：権限拒否AlertからSettingsを直接開く導線はありません。画像サイズ超過やアップロード失敗の画面内エラー処理は、登録mutation側の挙動に依存します。

## 10. 保存成功

正常系：

- 必須項目だけで犬を登録できる
- すべての任意項目と写真を含めて犬を登録できる
- Save押下後、登録中は二重送信できない
- Name、Breed、Gender、Birthday、Goal、PhotoがAPIへ正しく送信される
- 登録成功後、登録画面をdismissして新しい犬の詳細画面へ遷移する
- 詳細画面に保存した値が表示される
- 犬一覧へ戻ると新しい犬が1件だけ追加されている
- アプリ再起動後も登録した犬が表示される

異常・境界系：

- 同名犬を登録した場合、仕様どおり成功またはエラーになる
- 保存成功直後に戻る操作をしても重複登録されない
- 登録成功後の詳細遷移に失敗しても、犬が登録済みである事実を見失わない
- API成功後のキャッシュ更新に失敗しても一覧との不整合を検知できる

## 11. 保存失敗

期待する異常系：

- オフライン時にネットワークエラーを表示する
- APIタイムアウト時に登録中状態が永久に残らない
- GraphQL validation errorをユーザー向けに表示する
- 認証期限切れ時に認証更新またはログイン画面へ遷移する
- 写真アップロード失敗を明示する
- 登録失敗後も入力内容と選択画像を保持する
- 登録失敗後にSaveが再度有効になり、再試行できる
- 再試行で成功した場合、犬を1件だけ登録する
- エラー内容に内部情報、トークン、ストレージキーを表示しない

重要な現状差分：`handleSave`には`catch`がなく、`finally`で送信状態を解除するだけです。登録失敗を画面へ表示するstateがないため、ユーザー向けエラーと再試行可能性を保証するには実装変更が必要です。

## 12. アクセシビリティ・表示環境

正常系：

- CancelとSaveがそれぞれ明確なラベルを持つボタンとして読まれる
- Change photo、Name、Breed、Gender、BirthdayへVoiceOverで到達できる
- Birthdayの年・月・日と選択状態・無効状態を識別できる
- Goal周期の選択状態とSliderの値・範囲を認識できる
- 日本語・英語の双方でラベルと値が正しく表示される
- キーボード操作後もフォーカス順序が自然である
- 画像未設定でも犬名をアクセシビリティ情報として利用できる

異常・境界系：

- 文字サイズ最大時もSaveとCancelのタップ領域が失われない
- VoiceOver利用時に同じ「Save」「Cancel」が画面本体とBirthday Modalで混同されない
- Reduce Motion設定でもModal、画像選択、保存が完了する
- 端末回転または対応画面サイズ変更後も入力値を失わない

## 13. 証跡

各ケースで保存するもの：

- 初期状態、必須入力完了、Birthday Modal、Goal変更、画像選択、保存成功、各エラー表示のスクリーンショット
- 入力、Gender選択、Birthday選択、Goal操作、画像選択、保存・キャンセルの画面録画
- Maestro実行結果
- API、GraphQL、MinIOログ
- 使用した画像fixture名と入力データ
- 登録前後の犬件数と作成された犬ID
- 認証トークン、署名付きURL、ストレージ認証情報を除去した診断ログ

成功時は動画とスクリーンショットを保存します。失敗時は、上記に加えてAPIログ、fixture状態、Simulator状態、dev stackを保持します。
