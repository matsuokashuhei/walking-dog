# ログイン画面 E2Eテスト項目

ログイン画面 `/(auth)/login` の現行実装を基準に整理します。OTPはテスターがメールを確認してSimulatorへ手入力します。

## 1. 初期表示・遷移

- 未認証起動時にログイン画面を表示する
- App mark、見出し、説明、Email、Sign in、法務リンク、新規登録導線を表示する
- Email未入力ではSign inを無効にする
- 「Create an account」でサインアップ画面へ遷移する
- サインアップから戻るとログイン画面へ戻る
- 認証済みユーザーがログイン画面を開いた場合はWalkタブへ誘導する
- Dynamic Type、VoiceOver、英語・日本語、Light・Darkで操作できる

## 2. Email入力

- 有効なメールを入力するとSign inが有効になる
- 前後空白を除去して送信する
- 大文字、`+` alias、長い有効メールを扱う
- 空文字・空白だけでは送信しない
- 不正形式、制御文字、極端な長さを仕様どおり拒否する
- メール用キーボード、自動大文字化なし、自動修正なしを確認する
- 連続タップでOTP要求を重複送信しない

現状差分：クライアント検証は空でないことだけで、メール形式検証はありません。

## 3. OTP要求

- Sign inでローディングを表示する
- Cognitoから入力メールへOTPが届く
- 成功後にOTP入力へ切り替わり、送信先と桁数を表示する
- ネットワーク失敗、認証拒否、一般APIエラーを区別して表示する
- タイムアウト時に永久ローディングにならない
- 失敗後にEmailを修正して再試行できる
- レート制限を明示し、不要な連続送信を防ぐ

現状差分：レート制限専用表示とOTP再送ボタンはありません。

## 4. 人手によるOTP入力

- ランナーはOTP入力画面で一時停止し、送信先・手入力手順・timeoutを表示する
- 1桁入力、全桁paste、数字以外除外、最大桁数を確認する
- 規定桁数で検証を1回だけ開始する
- 検証中表示と入力無効化を確認する
- 正しいOTPで認証し、Walkタブへ遷移する
- 誤コード、期限切れ、ネットワーク、一般エラーを表示する
- 失敗後に入力をclearし、同じ誤コードを含め再試行できる
- 人による中断・timeoutを明示的なテスト結果として保存する

## 5. 認証状態

- access tokenとrefresh tokenをSecure Storeへ保存する
- アプリ再起動後に再ログインなしで認証状態を復元する
- access token期限切れ時にrefresh token rotationで更新する
- refresh応答にaccess/refresh tokenが欠ける場合は認証成功にしない
- refresh失敗時に保存状態を破棄してログインへ戻す
- OTP、session、tokenを画面録画以外のログへ残さない

## 6. 法務リンク・異常系

- TermsとPrivacy Policyが正しいURLを開く
- 外部ページからアプリへ戻れる
- URLを開けない・オフラインでもクラッシュしない
- API停止、Cognito停止、アプリbackground復帰で状態が破損しない

現状差分：`Linking.openURL`の失敗処理はありません。

## 7. 証跡

- 初期表示、OTP待ち、成功、各エラーのスクリーンショットと動画
- Maestro、API、認証ガードのログ
- OTP手入力の続行・中断・timeout結果
- OTP、session、tokenを除去した診断情報
