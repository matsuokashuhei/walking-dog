# サインアップ画面 E2Eテスト項目

サインアップ画面の現行実装を基準に、E2Eテスト項目を洗い出しました。OTPは「テスターがメールを確認して手入力し、続行操作を行う」前提です。

## 1. 初期表示

正常系：

- ログイン画面の「アカウントを作成」からサインアップ画面へ遷移する
- 見出し、説明、メール入力欄、「続ける」ボタン、補足文が表示される
- 利用規約とプライバシーポリシーへの同意文が表示される
- メール欄が未入力の場合、「続ける」が無効
- メール欄がメール用キーボードを使用する
- 自動大文字化、自動修正、スペルチェックが無効
- 戻る操作でログイン画面へ戻る
- ナビゲーション履歴がない状態の戻る操作でもログイン画面へ遷移する

異常・境界系：

- 画面を再表示したとき、前回の途中状態が意図せず残らない
- 小さい画面やキーボード表示中でもボタンと法務リンクへ到達できる
- Dynamic Typeを拡大しても重要な内容が欠けない
- VoiceOverで見出し、メール欄、ボタン、法務リンク、戻るボタンを識別できる

## 2. メール入力

正常系：

- 有効なメールアドレスを入力すると「続ける」が有効になる
- 前後の空白を除去してAPIへ送信する
- 大文字を含むメールアドレスを入力できる
- `+` を含むエイリアス形式を入力できる
- 長いが有効なメールアドレスを入力できる
- 入力後にキーボードを閉じても値が保持される

異常・境界系：

- 空文字では送信できない
- 空白だけでは送信できない
- `abc`、`abc@`、`@example.com` など不正形式を送信した場合の表示
- 改行や制御文字を含む入力
- 極端に長い入力
- 日本語や全角記号を含む入力
- 連続タップしてもOTP要求が重複送信されない
- 送信中は入力や再送信による二重リクエストを防ぐ

重要な現状差分：モバイル側は「空でないこと」しか検証していません。不正なメール形式もAPIへ送られます。形式検証をUI要件にするなら実装変更が必要です。

## 3. OTP要求

正常系：

- 「続ける」でローディング状態になる
- CognitoからOTPメールが届く
- 成功後、メール入力欄からOTP入力画面へ切り替わる
- 送信先メールアドレスと桁数が表示される
- APIが返した桁数に応じた入力セルが表示される
- OTP欄へフォーカスでき、数字キーボードが表示される

異常系：

- ネットワーク切断時に「ネットワーク接続を確認してください」
- APIエラー時に「コードを送信できませんでした」
- Cognitoが送信を拒否した場合に「このメールにコードを送れませんでした」
- APIタイムアウト時にローディングが永久に残らない
- エラー後、メールを修正して再試行できる
- 連続要求やCognitoレート制限時に、失敗理由を認識できる
- アプリをバックグラウンドへ移動して戻っても、状態が破損しない

重要な現状差分：レート制限専用のエラー表示と、OTP再送ボタンはありません。

## 4. 人手によるOTP入力

この地点でE2Eランナーを一時停止し、次を表示します。

- OTPの送信先
- テスターにメール確認とコード入力を求める案内
- 続行条件
- 待機タイムアウト

テスターがSimulatorへ直接OTPを入力すると、規定桁数に達した時点で自動検証が始まります。

正常系：

- 数字を1桁ずつ入力できる
- 完全なコードをペーストできる
- 数字以外は除外される
- 規定桁数を超えた入力は切り詰められる
- 規定桁数へ達したとき、検証要求が1回だけ送られる
- 検証中に「コードを確認中」が表示される
- 検証中はOTP欄が無効になる
- 正しいOTPで認証済み画面へ遷移する
- 認証トークンが保存され、アプリ再起動後も認証状態が維持される

異常系：

- 桁数不足では検証されない
- 誤ったOTPで「コードが正しくありません」
- 期限切れOTPで「コードの有効期限が切れています」
- 検証中のネットワーク切断でネットワークエラー
- その他のAPI失敗で「コードを確認できませんでした」
- 失敗後に入力がクリアされ、正しいコードを再入力できる
- 同じ誤コードを再入力しても再検証できる
- 検証ボタンの連打や同一コードの重複送信が起きない
- 待機中に人がキャンセルした場合、テストが明示的に中断扱いになる
- 待機タイムアウト時、失敗理由と証跡を保存する

## 5. 法務リンク

正常系：

- 「利用規約」で正しいURLを開く
- 「プライバシーポリシー」で正しいURLを開く
- 外部ページからアプリへ戻れる

異常系：

- URLを開けない場合にクラッシュしない
- オフライン時の挙動が明確
- 法務URLが未設定・不正な場合に検知できる

重要な現状差分：`Linking.openURL` の失敗を処理していないため、異常系を保証するには実装変更が必要です。

## 6. 証跡

各ケースで保存するもの：

- 開始時、OTP入力待ち、成功またはエラー表示のスクリーンショット
- 画面録画
- Maestro実行結果
- APIログ
- テスターの「続行」「中断」「タイムアウト」という判断
- OTPや認証トークンを除去した診断ログ
