# ユーザー編集画面 E2Eテスト項目

ユーザー編集画面 `/user/edit` の現行実装を基準に、E2Eテスト項目を洗い出しました。メールアドレスの変更は専用画面 `/settings/email` のテスト仕様として分離します。

## 1. 画面遷移・初期表示

正常系：

- Me画面のEditからユーザー編集画面へ遷移する
- Cancel、Save、プロフィール画像、Change photo、Name入力欄が表示される
- 現在のnameをName欄へ初期表示する
- nameがない場合はdisplayNameを初期表示する
- avatarがある場合は現在の画像を表示する
- avatarがなくavatarUrlがある場合はavatarUrlの画像を表示する
- 画像がない場合は表示名のinitialを表示する
- 初期名が空でなければSaveが有効である
- フォームをスクロールしてすべての操作へ到達できる

異常・境界系：

- ユーザー情報取得前に空の編集フォームを表示しない
- 画面を開き直したとき、キャンセル済みの変更が残らない
- 小さい画面やキーボード表示中でもCancel、Save、画像、Nameへ到達できる
- Dynamic Type最大時も操作ボタンとName欄が欠けない
- ライトモード・ダークモードで内容を判読できる
- VoiceOverでCancel、Save、画像変更、Nameを識別できる

## 2. ローディング・取得エラー

正常系：

- ユーザー情報の取得中はローディングインジケーターを表示する
- 取得成功後に編集フォームへ切り替わる
- 取得失敗時に「Failed to load user」を表示する
- エラー画面からRetryできる
- Retry成功後に編集フォームへ切り替わる

異常系：

- オフライン時にエラー画面を表示する
- APIタイムアウト時にローディングが永久に残らない
- ユーザーデータが空の場合にエラー画面を表示する
- Retryを連続タップしても不要な重複リクエストを発生させない
- 認証期限切れ時にトークン更新またはログイン画面へ遷移する
- 内部エラー詳細や認証情報を画面へ表示しない

## 3. Cancel操作

正常系：

- 変更せずCancelを押すとMe画面へ戻る
- Name変更後にCancelを押すと保存せずMe画面へ戻る
- 写真選択後にCancelを押すと保存せずMe画面へ戻る
- Cancel後、Me画面に元の名前と画像が表示される

異常・境界系：

- Cancelを連続タップしても余分な画面まで戻らない
- 画像ライブラリ表示中に戻っても編集画面の状態が破損しない
- 保存リクエスト送信中にCancelして二重遷移や不整合を起こさない
- 入力済み状態を確認なしに破棄する仕様が意図どおりである

重要な現状差分：未保存変更の確認ダイアログはありません。またCancelは`submitting`中も明示的には無効化されません。

## 4. Name入力とSave活性

正常系：

- 有効な名前を入力できる
- Name入力では単語単位の自動大文字化が設定される
- Name入力のReturn keyがDoneとして表示される
- 入力後にキーボードを閉じても値を保持する
- 前後の空白は保存時に除去される
- 有効なNameがある場合Saveできる
- 保存後、Me画面に更新した名前が表示される
- アプリ再起動後も更新した名前が表示される

異常・境界系：

- Nameが空文字の場合Saveは無効
- Nameが空白だけの場合Saveは無効
- 有効な名前から空文字へ変更するとSaveが無効になる
- 非常に短い名前を仕様どおり扱う
- 非常に長い名前でもフォームが破損しない
- 日本語、ラテン文字、スペース、ハイフン、アポストロフィを保存できる
- 絵文字、結合文字、右から左へ書く文字を安全に扱う
- 改行、制御文字、HTMLやスクリプト風文字列で表示やログが破損しない
- 保存中にNameを変更しても表示値と送信値が不整合にならない

重要な現状差分：クライアント側のName検証はtrim後に1文字以上であることだけです。最大長や文字種制限はありません。

## 5. プロフィール画像の初期表示

正常系：

- 保存済みavatarを表示する
- avatarがなくavatarUrlがある場合はavatarUrlを表示する
- 画像がない場合は表示名のinitialを表示する
- Nameを変更すると画像未設定時のinitialも更新される
- 画像の右下にカメラバッジを表示する
- 画像とChange photoを一つの操作ボタンとして扱う

異常・境界系：

- 不正、期限切れ、取得不能なavatar URLで画面がクラッシュしない
- 画像読み込み失敗時にinitialへフォールバックする
- 表示名が空の場合も安全なプレースホルダーを表示する
- 非常に長い表示名や絵文字からinitialを安全に生成する

## 6. プロフィール画像の選択

正常系：

- Change photoを押すと写真ライブラリ権限を要求する
- 権限許可後に画像ライブラリを開く
- 画像だけを選択対象にする
- 選択画面で編集・クロップできる
- 選択した画像を即座にプレビューする
- 選択をキャンセルした場合は現在画像を維持する
- ファイル名がない画像には`avatar.jpg`を使用する
- MIME typeをアップロード可能な形式へ正規化する
- Nameを変更せず画像だけ更新できる
- Nameと画像を同時に更新できる

異常系：

- 写真権限を拒否した場合、ローカライズされたAlertを表示する
- 権限拒否時に画像ライブラリを開かない
- 権限を恒久拒否した場合に再許可方法を理解できる
- assetがない選択結果でクラッシュしない
- 非対応MIME typeを安全に扱う
- 大容量画像でメモリ不足や長時間停止を起こさない
- 壊れた画像を選択した場合に失敗を明示する
- 画像選択を繰り返した場合、最後に選択した画像だけを保存する
- 画像アップロード失敗後も選択画像を保持し、再試行できる

重要な現状差分：権限拒否AlertからSettingsを直接開く導線はありません。既存画像を削除してinitialへ戻す操作もありません。

## 7. 保存成功

正常系：

- Nameだけの変更はJSON GraphQLリクエストで保存される
- 画像を含む変更はmultipart GraphQLリクエストで保存される
- 保存時にNameの前後空白を除去する
- 保存中はSaveを無効にして二重送信を防止する
- 保存成功後にMe画面へ戻る
- Me画面へ最新の名前と画像が反映される
- ユーザー画面のinitialも最新名に一致する
- アプリ再起動後も変更が永続化される
- 他画面で表示されるwalker名やavatarにも変更が反映される

異常・境界系：

- Saveを連続タップしても更新リクエストは1回だけ送信される
- 変更なしでSaveした場合のAPI呼び出し方針が一貫している
- 保存成功後の戻る遷移に失敗しても更新済み状態を見失わない
- キャッシュ更新後に古いプロフィールへ戻らない
- 複数端末から更新された場合の競合を仕様どおり扱う

重要な現状差分：変更有無を比較していないため、初期状態のままでもSaveを押すと更新APIを呼びます。

## 8. 保存失敗と再試行

正常系：

- 保存失敗時に「Failed to save user. Please try again.」のAlertを表示する
- Alertを閉じると編集画面に留まる
- 保存失敗後も入力したNameを保持する
- 保存失敗後も選択した画像を保持する
- 保存失敗後にSaveが再度有効になる
- 再試行で成功するとMe画面へ戻る

異常系：

- オフライン時に保存エラーを表示する
- APIタイムアウト時に保存中状態が永久に残らない
- GraphQL validation errorを内部情報なしで表示する
- 画像アップロード失敗を保存失敗として表示する
- 認証期限切れ時にトークン更新またはログイン画面へ遷移する
- 再試行でユーザーを重複作成せず、同じユーザーを更新する
- APIが成功した後に応答だけ失われた場合、再取得で実状態へ収束する
- Save失敗とCancelが競合して不整合を起こさない

## 9. 更新データの整合性

正常系：

- 保存後にuseMe系キャッシュが最新ユーザーへ更新される
- Me画面、設定画面、散歩履歴のwalker表示が同じ名前を使用する
- avatarの署名付きURLまたは公開URLが更新後に再取得される
- 古い画像キャッシュではなく新しい画像を表示する

異常・境界系：

- 保存後のキャッシュ更新失敗を検知する
- 画像URLが同一でも内容が更新された場合に新画像を表示する
- 名前だけ更新した場合に既存画像を失わない
- 画像だけ更新した場合に既存名を失わない
- 更新応答の一部フィールドが欠けても誤った空値で上書きしない

## 10. アクセシビリティ・表示環境

正常系：

- CancelとSaveが明確なアクセシビリティラベルを持つボタンとして読まれる
- Change photoが画像とテキストをまとめた一つのボタンとして読まれる
- Name入力欄をラベル付きで識別できる
- 保存可否がボタンのdisabled状態として伝わる
- 選択画像を表示名と関連付けて認識できる
- 日本語・英語でラベルとAlertが正しく表示される
- Dynamic Type最大時もスクロールですべての要素へ到達できる
- Reduce Motion設定でも画像選択、保存、戻る遷移が完了する

異常・境界系：

- 文字サイズ最大時もCancelとSaveのタップ領域が失われない
- VoiceOver利用中の写真ライブラリから編集画面へ正常に戻れる
- 画像だけに依存せず、Change photo操作を識別できる

## 11. 証跡

各ケースで保存するもの：

- ローディング、取得エラー、初期表示、Name変更、画像選択、権限拒否、保存成功、保存失敗のスクリーンショット
- Name入力、画像選択、Save、Cancel、Retryの画面録画
- Maestro実行結果
- API、GraphQL、MinIOログ
- 更新前後のユーザーfixtureと表示値の比較
- 使用した画像fixture名
- 認証トークン、署名付きURL、個人情報を必要以上に含まない診断ログ

成功時は動画とスクリーンショットを保存します。失敗時は、上記に加えてAPIログ、fixture状態、Simulator状態、dev stackを保持します。
