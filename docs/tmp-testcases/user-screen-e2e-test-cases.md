# ユーザー画面 E2Eテスト項目

Meタブのユーザー画面の現行実装を基準に、E2Eテスト項目を洗い出しました。ユーザー編集、メール変更、設定画面の内部仕様は、それぞれ別画面のテスト仕様として扱います。

## 1. 画面遷移・初期表示

正常系：

- 認証済み状態でMeタブを押すとユーザー画面へ遷移する
- 画面タイトル「Me」が表示される
- ヘッダー右側に「Edit」ボタンが表示される
- ユーザーのアバター、表示名、メールアドレス、利用開始月が表示される
- 生涯集計として散歩回数、距離、合計時間、犬の数が表示される
- 今週の合計距離と月曜から日曜までの棒グラフが表示される
- 「Change email」と「Settings」の導線が表示される
- Change passwordの導線は表示されない
- 画面をスクロールしてすべての導線へ到達できる
- 別タブへ移動して戻ったとき、ユーザー画面が正常に再表示される

異常・境界系：

- 未認証状態ではユーザー情報を表示せず、認証画面へ誘導される
- アプリをバックグラウンドへ移動して戻っても表示が破損しない
- 小さい画面でも集計、グラフ、各導線へ到達できる
- Dynamic Type最大時も重要な値と操作ボタンが欠けない
- ライトモード・ダークモードの双方で情報を判読できる
- VoiceOverで見出し、プロフィール情報、集計、各導線を識別できる

## 2. ローディング

正常系：

- ユーザー情報の取得中はローディングインジケーターが表示される
- 取得中に前回値や空の集計を誤表示しない
- 取得完了後にプロフィール画面へ切り替わる

異常・境界系：

- API応答が遅い場合もローディング状態を維持する
- タイムアウト時にローディングが永久に残らない
- ローディング中に他タブへ移動して戻ってもクラッシュしない
- 認証状態が確定する前に不要なプロフィールAPIを送信しない

## 3. 取得エラーと再試行

正常系：

- ユーザー情報の取得失敗時に「Failed to load user」を表示する
- エラー画面からRetryを実行できる
- Retry成功後にプロフィール画面へ切り替わる
- エラー後もアプリ全体のタブ操作が破損しない

異常系：

- オフライン時にエラー画面を表示する
- APIタイムアウト時に再試行できる
- GraphQLエラー時に内部エラー詳細を表示しない
- 認証期限切れ時にトークン更新またはログイン画面への遷移を行う
- Retryを連続タップしても不要な重複リクエストを発生させない
- Retryが再び失敗した場合もエラー画面を維持する
- キャッシュ済みデータがある場合の表示方針が一貫している

## 4. ユーザー識別情報

正常系：

- `name`がある場合はnameを表示する
- nameがなく`displayName`がある場合はdisplayNameを表示する
- nameとdisplayNameがない場合は「Unknown user」を表示する
- 表示名の先頭文字がアバターのinitialになる
- 表示名がない場合は`?`をinitialとして表示する
- avatar URLがある場合はユーザー画像を表示する
- avatar URLがない場合はinitialを表示する
- メールアドレスを表示する
- createdAtをロケールに応じた年月へ変換し「Walking since ...」として表示する

異常・境界系：

- 表示名が空文字または空白だけの場合はUnknown userへフォールバックする
- 非常に長い表示名を1行に収め、画面を破損させない
- 絵文字、漢字、結合文字からinitialを安全に生成する
- 非常に長いメールアドレスを1行に収める
- 不正なavatar URLや画像取得失敗時にinitialへフォールバックする
- createdAtが不正な場合は日付を`--`として表示する
- createdAtが未来の場合の表示を確認する
- タイムゾーン差で利用開始月が前後しない

重要な現状差分：表示名とメールは`numberOfLines={1}`で省略されます。avatar URLの読み込み失敗時のフォールバック可否はUserAvatarの画像処理に依存します。

## 5. 生涯集計

正常系：

- 散歩回数を整数で表示する
- 総距離をkm単位、小数点以下1桁で表示する
- 合計時間をロケールに応じた時間表記で表示する
- 登録犬数を整数で表示する
- API fixtureの値と表示値が一致する
- 新しい散歩完了後、散歩回数・距離・時間が増加する
- 犬登録後、犬数が増加する
- 犬削除後、犬数が減少する
- アプリ再起動後も同じ集計が表示される

異常・境界系：

- すべて0の場合、0を正しく表示する
- 距離が1km未満の場合も正しい小数値を表示する
- 長時間・長距離・多数の散歩でも値が欠けない
- 負の集計値をAPIが返した場合に不正データを検知する
- 非整数やNaN相当の値で画面がクラッシュしない
- 距離単位設定をmileへ変更した場合の表示仕様を確認する

重要な現状差分：ユーザー画面の距離表示は`km`固定で組み立てられています。Settingsのunits設定との連動は確認できないため、mile表示を要件にする場合は実装変更が必要です。

## 6. 今週の散歩グラフ

正常系：

- 週の開始を月曜日として月曜から日曜まで7列表示する
- 現在週に含まれる散歩だけを集計する
- 同じ日に複数散歩がある場合、距離を合算する
- 各日の距離をkm、小数点以下1桁で表示する
- 散歩がない日は値ラベルを空にし、最小高のバーを表示する
- 最長距離の日を最大高として、他の日を相対高で表示する
- 今日のバーだけsuccess色で強調する
- 散歩済みの過去日をinteractive色で表示する
- 散歩がない日はsurface色で表示する
- 週合計距離がAPI fixtureの合計と一致する
- 日曜から月曜へ日付が変わると新しい週へ切り替わる

異常・境界系：

- 今週の散歩が0件でも7日分を表示し、合計0を表示する
- 週境界直前・直後の散歩を正しい週へ分類する
- 日曜の散歩を同じ週の最終日として扱う
- UTC日時を端末ローカル日付へ正しく変換する
- 夏時間開始・終了地域でも日付がずれない
- 未来日時の散歩をどのように扱うか確認する
- 負の距離をグラフへ反映しない
- recentWalksが100件を超える週でも合計が欠落しない

重要な現状差分：プロフィールqueryは`first: 100`で履歴を取得し、そのnodesから週間グラフを計算します。1週間に100件を超える散歩がある場合、グラフが過少集計になる可能性があります。

## 7. Edit導線

正常系：

- ヘッダーのEditを押すと `/user/edit` へ遷移する
- 編集画面で変更を保存して戻ると、表示名とavatarが更新される
- 編集をキャンセルして戻ると、元の情報を維持する

異常・境界系：

- Editを連続タップしても編集画面が多重に積まれない
- 編集保存後の再取得失敗時に古い値との不整合を検知する
- ユーザー情報取得中またはエラー中はEditを表示しない

## 8. Change email導線

正常系：

- Change emailを押すと `/settings/email` へ遷移する
- メール変更成功後に戻ると新しいメールアドレスが表示される
- メール変更をキャンセルした場合は元のメールを維持する

異常・境界系：

- Change emailを連続タップしても画面が多重に積まれない
- メール変更後のトークン更新失敗を適切に扱う
- 変更後のプロフィール再取得失敗時に不整合を検知する

## 9. Settings導線

正常系：

- Settingsを押すと `/settings` へ遷移する
- Settingsから戻るとユーザー画面へ復帰する
- 言語、テーマ、単位を変更して戻った場合、ユーザー画面へ適用される

異常・境界系：

- Settingsを連続タップしても画面が多重に積まれない
- 設定変更中にアプリを再起動しても保存済み設定を反映する
- 不正または未保存の設定値でユーザー画面がクラッシュしない

## 10. 更新・データ整合性

正常系：

- 散歩終了後にMeタブへ移動すると集計へ反映される
- すでにMeタブを開いている状態でも、再訪または再取得で最新値へ更新される
- 別画面でユーザー名やavatarを変更した後に最新値が表示される
- 別画面で犬を追加・削除した後に犬数が更新される
- APIレスポンスの散歩総数・総距離・総時間と画面値が一致する

異常・境界系：

- 一部の集計だけ更新された中間状態を表示しない
- キャッシュとAPIの値が異なる場合、最終的にAPIの正しい値へ収束する
- 再取得中に前回の正しい値を不用意に0へ戻さない
- 複数端末で更新されたプロフィールを再取得できる

## 11. アクセシビリティ・表示環境

正常系：

- 「Me」がheaderとして読まれる
- Edit、Change email、Settingsがボタンとして読まれる
- avatarから表示名を識別できる
- 4つの生涯集計を値と単位の組として理解できる
- 週間グラフをVoiceOver利用者も日付・距離・今日の情報として理解できる
- 日本語・英語で月名、曜日、時間、距離が正しくローカライズされる
- Dynamic Type最大時もスクロールですべての情報へ到達できる
- Reduce Motion設定でも遷移と更新が完了する

異常・境界系：

- 色だけに依存せず、今日と他の日を識別できる
- 空の棒グラフでも「0」または散歩なしを認識できる
- 長い値とラベルで読み上げ順序が崩れない

重要な現状差分：週間グラフのバーにはtestIDがありますが、日付・距離・今日をまとめた明示的なアクセシビリティラベルはありません。色と視覚配置への依存を減らすには実装変更が必要です。

## 12. 証跡

各ケースで保存するもの：

- ローディング、取得エラー、データ0件、通常プロフィール、大きい集計、週間グラフ、各遷移のスクリーンショット
- Retry、Edit、Change email、Settings、散歩後の集計更新の画面録画
- Maestro実行結果
- APIおよびGraphQLログ
- 使用した固定ユーザー、犬、散歩fixture名
- API fixture値と画面表示値の比較結果
- 認証トークン、メール変更用session、個人情報を必要以上に含まない診断ログ

成功時は動画とスクリーンショットを保存します。失敗時は、上記に加えてAPIログ、fixture状態、Simulator状態、dev stackを保持します。
