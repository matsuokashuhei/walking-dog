# 散歩詳細画面 E2Eテスト項目

散歩詳細画面 `/walks/{id}` の現行実装を基準に、E2Eテスト項目を洗い出しました。散歩履歴一覧と犬プロフィール内の履歴一覧は別画面のテスト仕様として扱います。

## 1. 画面遷移・初期表示

正常系：

- 散歩終了成功後に作成されたwalkIdの詳細画面へ遷移する
- 犬プロフィールまたは履歴一覧から対象walkIdの詳細画面へ遷移する
- 地図、日付、Walk Detailタイトル、犬名、開始・終了時刻を表示する
- 距離、時間、ペースを表示する
- 担当者がある場合はwalker情報を表示する
- イベントがある場合はイベントタイムラインを表示する
- 画面を縦スクロールしてすべての情報へ到達できる
- 戻る操作で遷移元へ戻る

異常・境界系：

- idが空、不正、存在しない場合に永久ローディングにならず、エラーまたはNot Foundを表示する
- 未認証状態では詳細を表示せず認証画面へ誘導する
- 他ユーザーのwalkIdへアクセスした場合に情報を表示しない
- アプリ再起動後、deep linkから同じ詳細を開ける
- 小さい画面とDynamic Type最大時でも全情報へ到達できる
- ライトモード・ダークモードで地図overlayと文字を判読できる

重要な現状差分：現行画面は`isLoading`、walk未取得、ViewModel未生成のすべてで同じActivityIndicatorを表示します。取得エラーやNot Foundを表示する分岐がないため、失敗時に永久ローディングへ見える可能性があります。

## 2. Active walkとの競合

正常系：

- active walkがない場合は指定された完了済み散歩の詳細を表示する
- active walkが存在しphaseがrecordingの場合は詳細表示を中止する
- active walkのwalkIdを指定して`/walk-recording`へreplaceする
- 戻る操作で詳細画面とrecording画面を往復するループを作らない

異常・境界系：

- URLのwalkIdとactive walkIdが異なる場合でも現在のrecordingを優先する仕様を確認する
- phaseがrecordingなのにactiveWalkIdがない場合、誤った詳細を表示しない
- replace中に詳細データ取得が完了しても一瞬表示しない
- staleなwalk storeで完了済み散歩をrecordingへ誤誘導しない

## 3. ルート地図

正常系：

- track pointを緯度経度へ変換して地図に表示する
- 2点以上ある場合だけPolylineを描画する
- Polylineを成功色、一定幅、round cap/joinで描画する
- track pointsの中央要素をinitialRegionの中心にする
- track pointがない場合は東京駅を初期中心として表示する
- 座標付きイベントを種別ごとの絵文字markerとして表示する
- 座標なしイベントは地図markerとして表示しない
- markerをVoiceOverで「Pee event」「Poop event」「Photo event」と識別できる

異常・境界系：

- track pointが0件でも地図がクラッシュしない
- track pointが1件の場合はPolylineを描かず安全に表示する
- 非常に多数のtrack pointsでも描画が停止しない
- 不正な緯度経度、NaN相当、範囲外座標を安全に扱う
- GPSジャンプを含むルートでも地図が全世界表示など不自然なregionにならない
- 日付変更線を跨ぐルートを正しく表示する
- 同一座標が連続してもPolylineが破損しない
- MapViewの読み込み失敗やオフライン時にも他の詳細情報を閲覧できる
- 同じevent IDが重複してもmarker key衝突を検知する

重要な現状差分：initialRegionの中心はtrack point配列の中央要素であり、ルート全体が収まるregion計算ではありません。全ルート表示を要件にする場合は実装変更が必要です。

## 4. 日付・時刻

正常系：

- startedAtを短い日付形式へ変換して表示する
- startedAtをローカル時刻へ変換して表示する
- endedAtがある場合は開始・終了時刻を区切り文字付きで表示する
- endedAtがない場合は開始時刻だけを表示する
- VoiceOverでは「Start time」「End time」の文脈を含めて読み上げる
- 日本語・英語のロケールに応じた日付・時刻を表示する

異常・境界系：

- 不正なstartedAtで画面がクラッシュしない
- endedAtがstartedAtより前の場合に不正データを検知する
- 日付跨ぎ・月跨ぎ・年跨ぎの散歩を正しく表示する
- UTCと端末タイムゾーンの差で日付が誤らない
- 夏時間開始・終了を跨いでも表示とdurationが矛盾しない
- endedAtがnullの完了済み散歩をどのように表示するか確認する

## 5. 犬情報

正常系：

- 1頭散歩では対象犬名を表示する
- 複数頭散歩では犬名をカンマ区切りで表示する
- API fixtureの犬と表示名が一致する

異常・境界系：

- dogsが空配列の場合に空白だけでなく意味のある表示を行う
- 同名犬が複数いる場合も散歩参加犬数を正しく扱う
- 非常に長い犬名・多数の犬名でレイアウトが破損しない
- 削除済み犬を含む過去散歩でも当時の犬名を表示できる
- 犬名に絵文字、結合文字、右から左へ書く文字があっても安全に表示する

## 6. 距離・時間・ペース

正常系：

- distanceMをkm、小数点以下2桁で表示する
- durationSecを読みやすい時間表記で表示する
- durationSecとdistanceMからペースを計算する
- 3つのメトリクスをDistance、Time、Paceの順で表示する
- API fixtureの値と画面表示値が一致する
- 0m、0秒を安全な値として表示する

異常・境界系：

- distanceMがnullの場合は0として表示する
- durationSecがnullの場合は0として表示する
- 距離0で時間だけある場合、0除算せずペースを安全に表示する
- 時間0で距離だけある場合、ペースを安全に表示する
- 負の距離・時間をAPIが返した場合に不正データを検知する
- 非常に長時間・長距離でも値が欠けない
- km/mile設定を変更した場合の表示仕様を確認する

重要な現状差分：詳細画面の距離とペースはkm固定で組み立てられ、Settingsのunits設定を参照していません。mile表示を要件にする場合は実装変更が必要です。

## 7. Walker情報

正常系：

- walkerがある場合にWalkerセクションを表示する
- walkerのnameがある場合はnameを表示する
- nameがなくdisplayNameがある場合はdisplayNameを表示する
- avatarがある場合は画像を表示する
- avatarがなくavatarUrlがある場合はavatarUrlを表示する
- 画像がない場合は表示名のinitialを表示する
- walkerがない場合はセクション全体を表示しない

異常・境界系：

- walkerの表示名がnullでも画面がクラッシュしない
- 表示名が空白だけの場合に`?`へフォールバックする
- 不正・期限切れavatar URLでinitialへフォールバックする
- 非常に長いwalker名でもレイアウトが破損しない
- ユーザー名変更後も過去散歩で期待する名前を表示する

重要な現状差分：walkerのname/displayNameがnullの場合、initialは`?`ですが表示名自体はnullです。空白だけの名前ではinitialが空になる可能性があります。

## 8. イベントタイムライン

正常系：

- イベントが0件の場合はタイムラインカードを表示しない
- Pee、Poop、Photoをイベント種別の絵文字とラベルで表示する
- 各イベントのoccurredAtをローカル時刻で表示する
- APIから返された順序でイベントを表示する
- 散歩中に記録したすべてのイベントが1件ずつ表示される
- 座標付きイベントは地図markerとタイムラインの双方に表示される
- 座標なしイベントはタイムラインだけに表示される

異常・境界系：

- occurredAtが不正なイベントで画面がクラッシュしない
- walk開始前・終了後の時刻を持つイベントを不正データとして検知する
- 不明なeventTypeを安全に扱う
- 同一event IDの重複を検知する
- 非常に多数のイベントでもスクロール・描画性能を維持する
- イベント順が時系列でない場合の表示方針を確認する
- 削除済み犬に紐づくイベントも表示できる

重要な現状差分：タイムライン側でイベントを時刻順にsortせず、API配列の順序をそのまま表示します。

## 9. 写真イベントと全画面表示

正常系：

- photoイベントにphotoUrlがある場合だけサムネイルを表示する
- サムネイルをボタンとして操作できる
- サムネイルにアクセシビリティラベルとヒントを設定する
- タップするとModalで写真を全画面表示する
- 写真をcontainで表示し、全体を確認できる
- CloseボタンでModalを閉じる
- システム戻る操作でもModalを閉じる
- Safe Areaを考慮した位置にCloseボタンを表示する

異常系：

- photoイベントにphotoUrlがない場合はサムネイルを表示しない
- 期限切れ、404、壊れたphoto URLで画面がクラッシュしない
- サムネイル読み込み失敗を明示またはプレースホルダー表示する
- 全画面画像の読み込み失敗時にModalを閉じられる
- オフライン時もModalを閉じて詳細画面へ戻れる
- サムネイルを連続タップしてModalを重複表示しない
- Modal表示中の回転・バックグラウンド復帰で状態が破損しない
- 非常に大きい画像でメモリ不足を起こさない

重要な現状差分：画像読み込み失敗時のプレースホルダーやエラーメッセージはありません。

## 10. データ取得・更新

正常系：

- 指定walkIdで詳細APIを1回取得する
- 散歩終了直後でも確定済み距離、時間、points、eventsを取得する
- track point workerの処理完了後に完全なルートを表示する
- 画面を開き直した場合に最新データを取得する
- アプリ再起動後も同じ詳細を表示する

異常系：

- API取得失敗時にエラー表示とRetryを提供する
- Not Found時に散歩が存在しないことを表示する
- タイムアウト時に永久ローディングにならない
- worker処理中の一時的なpoints不足と本当の0件を区別する
- 認証期限切れ時に更新またはログイン画面へ遷移する
- APIレスポンスの一部フィールドが欠けても誤った成功表示にしない
- 内部エラー、トークン、署名付きURLをユーザーへ表示しない

重要な現状差分：現行画面にはエラー表示、Retry、Not Found表示がありません。

## 11. アクセシビリティ・表示環境

正常系：

- 日付、犬名、開始・終了時刻を意味のある順序で読み上げる
- Distance、Time、Paceを値と単位の組で認識できる
- map markerをイベント種別として識別できる
- walker画像またはinitialから担当者を識別できる
- タイムラインの時刻、イベント種別、写真を関連付けて読み上げる
- 写真のOpenとCloseをVoiceOverで操作できる
- 日本語・英語で日付、時刻、単位、イベントラベルを正しく表示する
- Dynamic Type最大時もスクロールですべての情報へ到達できる
- Reduce Motion設定でも写真Modalと画面遷移が完了する

異常・境界系：

- MapViewを操作できない利用者もルート・イベント情報をタイムラインから理解できる
- 色だけに依存せずイベント種別とメトリクスを識別できる
- 非常に長い犬名・walker名で読み上げ順序が崩れない

## 12. 証跡

各ケースで保存するもの：

- ローディング、通常詳細、ルート0点・1点・複数点、複数犬、walker、イベント、写真Modal、取得エラー、Not Foundのスクリーンショット
- 詳細遷移、地図表示、スクロール、写真Open/Close、Retry、active walk redirectの画面録画
- Maestro実行結果
- API、track-point worker、DynamoDB、MinIOログ
- 使用したwalk fixture、walkId、犬、walker、points、eventsの期待値
- 表示された距離、時間、ペース、イベント件数とfixtureの比較結果
- 認証トークン、署名付きURL、詳細な位置情報を必要以上に含まない診断ログ

成功時は動画とスクリーンショットを保存します。失敗時は、上記に加えてAPIログ、worker・fixture状態、Simulator状態、dev stackを保持します。
