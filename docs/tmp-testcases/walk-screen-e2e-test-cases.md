# 散歩画面 E2Eテスト項目

Walkタブの現行実装を基準に、散歩開始前のready状態と記録中のrecording状態を一つの画面状態機械としてE2Eテスト項目に整理しました。散歩終了後の詳細画面と履歴一覧は別画面のテスト仕様として扱います。

## 1. 画面遷移・基本表示

正常系：

- 認証済み状態でWalkタブを押すと散歩画面へ遷移する
- ready状態でプレビューマップ、上部チップ、下部フローティングシートが表示される
- 散歩開始後も同じWalkタブ内でrecording状態へ切り替わる
- readyからrecordingへ切り替わる際にマップを再mountしない
- recording状態では記録用マップ、犬情報、メトリクス、イベント操作、終了操作が表示される
- 他タブへ移動して戻った場合も進行中の散歩を復元する
- アプリ再起動後に進行中の散歩を復元する

異常・境界系：

- 未認証状態ではWalk画面を表示せず認証画面へ誘導する
- 不明なphaseで空白画面にならず、安全な状態へ復帰する
- readyからrecordingへの切り替え中に操作を連打しても状態が重複しない
- バックグラウンド移行・復帰で地図と下部操作面が破損しない
- 小さい画面やDynamic Type最大時でも主要操作へ到達できる
- ライトモード・ダークモードでマップoverlayと操作面を判読できる

重要な現状差分：phaseがreadyまたはrecording以外の場合、routeは`null`を返します。finishedや不正状態で空白画面が表示される可能性があります。

## 2. 犬が未登録の状態

正常系：

- 犬が0件の場合、犬未登録のイラスト、見出し、説明を表示する
- 「Add your first dog」ボタンを表示する
- CTAを押すと犬登録画面 `/dogs/new` へ遷移する
- 犬登録後にWalkタブへ戻ると登録犬を選択できる

異常・境界系：

- 犬一覧取得中に犬0件状態を誤表示しない
- 犬一覧取得失敗を犬0件として扱わない
- CTAを連続タップしても登録画面を多重に積まない
- 犬登録をキャンセルして戻った場合、犬未登録状態へ正常に戻る

重要な現状差分：Walk画面側には犬一覧の明示的なローディング・エラー表示が確認できず、`useMe`の状態次第で犬0件と取得失敗を区別できない可能性があります。

## 3. 1頭での散歩準備

正常系：

- 犬が1頭の場合、その犬を自動選択した状態で表示する
- 犬名とavatarを上部チップと選択カードに表示する
- 今日の散歩距離・時間・目標進捗を表示する
- 犬が選択済みの場合START WALKを有効にする
- START WALKを押すと開始処理へ進む

異常・境界系：

- 犬データにavatarがない場合もプレースホルダーを表示する
- 非常に長い犬名でもチップとカードが破損しない
- 同期中に犬が削除された場合、存在しない犬で開始しない
- START WALKを連続タップしても開始リクエストを1回だけ送信する
- 開始処理中はSTART WALKをローディング・無効状態にする

## 4. 複数頭での散歩準備

正常系：

- 犬が2頭以上の場合、「Walking with」を表示する
- 各犬を個別に選択・選択解除できる
- Select allですべての犬を選択できる
- 全選択時は操作表示がDeselect allへ切り替わる
- Deselect allですべての選択を解除できる
- 1頭以上選択されている場合だけSTART WALKを有効にする
- 選択犬が上部チップへ反映される
- 選択した複数犬すべてを散歩開始APIへ送信する

異常・境界系：

- 0頭選択ではSTART WALKを実行できない
- 同名犬をIDで正しく区別して選択できる
- 多数の犬を横・縦スクロールして選択できる
- 選択後に犬一覧が更新され、存在しないIDが混ざった場合は無効IDを除外する
- Select allを連打しても選択状態が破損しない
- 開始処理中に犬選択を変更して送信対象と表示が不一致にならない

## 5. 位置情報とプレビューマップ

正常系：

- foreground位置情報権限を要求する
- 許可後、現在地付近をプレビューマップへ表示する
- GPS更新後に固定の初期座標から現在地へ移動する
- START WALK前に選択犬と現在地を確認できる

異常系：

- foreground位置情報を拒否した場合に開始可否と案内が明確である
- background位置情報を拒否してもforeground記録へフォールバックする
- 位置情報サービスがOFFの場合に明示的な案内を表示する
- GPS取得タイムアウト時に永久待機しない
- 位置精度が低い場合に異常な距離を記録しない
- simulator location未設定でもクラッシュしない
- 緯度経度が不正な場合にマップとstoreを破損しない
- 権限変更後にアプリへ戻ると状態を再評価する

## 6. 散歩開始

正常系：

- 選択犬を指定して散歩開始APIを呼ぶ
- 開始成功後にwalkIdとstartedAtをstoreへ保存する
- recording状態へ切り替わる
- 背景位置情報が許可されている場合はbackground trackingを開始する
- foreground trackingを開始する
- Live ActivityとWatch連携用snapshotを開始する
- 選択犬をrecording画面へ引き継ぐ

異常系：

- ネットワーク切断時に開始失敗を表示する
- APIタイムアウト時に開始中状態が永久に残らない
- 別のactive walkが存在する場合に重複散歩を開始しない
- 認証期限切れ時に更新または再ログインへ誘導する
- 位置情報開始に失敗した場合、API上のactive walkとの不整合を解消する
- API開始成功後にローカル初期化が失敗した場合、復旧可能な状態を保持する
- 開始失敗後に再試行できる
- 再試行でactive walkを重複作成しない

## 7. 記録中の基本表示

正常系：

- LIVE状態として記録中パネルを表示する
- 1頭の場合は犬名と時間帯に応じたMorning/Afternoon/Evening Walkを表示する
- 複数頭の場合は犬名を連結しGroup Walkを表示する
- 経過時間を1秒ごとに更新する
- 移動に応じて距離を更新する
- 時間と距離からペースを更新する
- Settingsのkm/mile設定を距離とペースへ反映する
- 最新位置に犬avatar付きの現在地markerを表示する
- 取得済みtrack pointsを同じwalkIdへ記録する

異常・境界系：

- startedAtがない状態でも画面がクラッシュしない
- walkIdがないrecording状態を検知して安全に復旧する
- GPSが一時停止しても経過時間を継続し、距離を不正に増やさない
- GPSジャンプや極端な速度を距離へ無制限に反映しない
- 0m時のペースを安全な表記にする
- 非常に長時間の散歩でも時刻表示が欠けない
- timezoneや日付跨ぎで経過時間が巻き戻らない
- オフラインでもローカル記録を維持し、復帰後に同期する

## 8. パネルの縮小・展開

正常系：

- Minimizeでexpanded panelからminimized controlsへ切り替わる
- 縮小中はイベント操作と終了スライダーを表示しない
- 縮小中も犬、LIVE、時間、距離を表示する
- Expandでexpanded panelへ戻る
- Expandにアクセシビリティヒントを設定する
- 縮小・展開してもマップを再mountしない
- 縮小状態をstoreで一貫して管理する

異常・境界系：

- 縮小・展開を連打してもoverlayが重複しない
- layout animation中に操作してもパネルが画面外へ消えない
- バックグラウンド復帰後も縮小状態が破損しない
- Dynamic Type最大時もExpand操作へ到達できる

## 9. Pee・Poopイベント

正常系：

- 1頭散歩ではPeeとPoopを対象犬へ記録する
- 複数頭散歩では犬ごとのPeeとPoopボタンを表示する
- イベントにwalkId、dogId、eventType、occurredAtを含める
- 最新GPS点がある場合はlat/lngを含める
- GPS点がない場合も位置なしイベントとして記録できる
- API成功後にイベントをローカルstoreへ追加する
- 成功時に軽いhaptic feedbackを実行する
- 記録したイベントmarkerをマップへ表示する

異常系：

- walkIdがない場合はイベントを送信しない
- API送信中は同じ操作を無効にする
- ネットワーク切断時に記録失敗Alertを表示する
- API失敗時にローカルstoreへ成功扱いで追加しない
- 連打でイベントを意図せず重複記録しない
- オフラインoutbox対象のイベントは復帰後に一度だけ同期する
- 同期再試行で同じイベントを重複作成しない
- 一方の犬のイベントを別犬へ誤記録しない

## 10. 写真イベント

正常系：

- Photo操作でカメラ権限を要求する
- 権限許可後に実カメラUIを表示する
- 撮影をキャンセルした場合はイベントを作成しない
- 撮影画像を正しいwalkIdと犬へアップロードする
- 写真イベントに撮影時刻と最新位置を記録する
- アップロード成功後にstoreとマップへイベントを追加する
- deep linkまたはroute paramの`action=camera`から記録中のカメラを開ける
- camera action処理後にroute paramを消去する

異常系：

- カメラ権限拒否時に案内を表示する
- カメラが利用不能なSimulatorで明示的に失敗する
- walkIdがない場合にcamera actionを実行しない
- ready状態でcamera actionを受けても起動しない
- 撮影失敗・画像処理失敗・アップロード失敗を明示する
- 大容量画像でメモリ不足を起こさない
- オフライン時に写真イベントを失わず、再試行方針を明示する
- 同じroute paramでカメラを繰り返し起動しない
- 写真アップロード失敗をPee/Poop成功と混同しない

## 11. バックグラウンド・復帰・外部連携

正常系：

- 記録中にアプリをバックグラウンドへ移しても許可範囲でGPS記録を継続する
- foregroundへ戻ると同じwalkId、経過時間、距離、イベントを復元する
- persisted active walk sessionから状態をhydrateする
- Live Activityに犬、時間、距離、イベントを同期する
- Watchへactive walk snapshotを同期する
- Live Activityやdeep linkからWalkタブのrecording状態へ復帰する

異常・境界系：

- background権限なしではforeground trackingだけを使用する
- OSによるプロセス終了後もサーバーと永続化状態から復旧する
- 古いsnapshotや別walkIdのWatch commandを現在の散歩へ適用しない
- API上にactive walkがなくローカルだけ残る場合に不整合を解消する
- API上にactive walkがありローカル状態がない場合に復元する
- refresh token更新失敗時に記録データを失わない

## 12. 散歩終了操作

正常系：

- End Walkスライダーを95%以上移動すると終了処理を1回実行する
- しきい値未満で離すとスライダーが開始位置へ戻る
- タップまたはVoiceOver activateでも終了できる
- 終了処理中はスライダーを無効にする
- 終了APIが距離、時間、track points、イベントを確定する
- 終了成功後に `/walks/{walkId}` の詳細画面へ遷移する
- 詳細画面への遷移後にwalk storeをresetする
- Live Activity、background tracking、Watch snapshotを終了する

異常系：

- walkIdがない場合は終了APIを呼ばない
- 終了操作を連打・再スライドしてもAPIを1回だけ呼ぶ
- drag中断時は開始位置へ戻る
- 終了API失敗時に「Failed to finish walk」を表示する
- 終了失敗後にrecording状態を維持し、再試行できる
- 終了失敗後にスライダーが再び操作可能になる
- API成功後に詳細遷移が失敗しても完了済みwalkを失わない
- queue未送信track pointsやeventsを確定前に失わない
- 終了中のアプリ強制終了後にactive/finished状態を正しく復旧する

重要な現状差分：終了失敗はAlert表示されます。終了成功後は詳細へpushしてからstoreをresetします。途中失敗時のAPI・store整合性は重点的なE2E確認が必要です。

## 13. 表示・アクセシビリティ

正常系：

- START WALK、犬選択、Select all、Pee、Poop、Photo、Minimize、Expand、End WalkをVoiceOverで識別できる
- 複数犬のイベントボタンは犬名とイベント種別を読み上げる
- End Walkはbutton roleとdisabled状態を持つ
- 時間、距離、ペースを値と単位の組として理解できる
- 色だけに依存せずLIVE、選択、無効、今日の状態を識別できる
- 日本語・英語、km・mile、ライト・ダークで正しく表示される
- Reduce Motion設定でもready/recording、縮小/展開、終了が完了する

異常・境界系：

- Dynamic Type最大時に地図を覆い尽くさず主要操作へ到達できる
- 同名犬をVoiceOverで選択・イベント記録時に区別できる
- 横スクロールするイベント操作へVoiceOverで到達できる
- 終了スライダーをドラッグできない利用者もactivateで終了できる

## 14. 証跡

各ケースで保存するもの：

- 犬未登録、1頭準備、複数頭準備、位置権限、recording、縮小、イベント、写真、終了成功、終了失敗のスクリーンショット
- 犬選択、GPS移動、開始、Pee/Poop、撮影、バックグラウンド復帰、終了の画面録画
- Maestro実行結果
- API、worker、DynamoDB、MinIOログ
- 使用した犬fixture、GPS route、権限状態、walkId
- track points、イベント、最終距離・時間の期待値と実値
- 認証トークン、署名付きURL、位置情報を必要以上に公開しない診断ログ

成功時は動画とスクリーンショットを保存します。失敗時は、上記に加えてAPIログ、queue・fixture状態、Simulator状態、dev stackを保持します。
